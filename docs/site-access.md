# Доступ к сайту

## Включение и отзыв

1. Открываем обычную HTTP/HTTPS-страницу и popup расширения.
2. Нажимаем «Разрешить для этого сайта» и подтверждаем запрос браузера.
3. После успешной регистрации сборщика нажимаем «Перезагрузить вкладку».
4. После запуска bridge видим найденные обработчики либо подтверждённый пустой результат.
5. Для остановки нажимаем «Отозвать доступ». Результаты затронутого сайта удаляются из всех вкладок.

Отказ в диалоге не считается ошибкой: запрос можно повторить. Выдача разрешения сама по себе не перезагружает вкладку. Если страница изменилась во время запроса, popup перечитывает её состояние и не применяет прежнее действие к другому сайту.

## Область разрешения

Запрашиваем одну схему и точный hostname, например `https://example.com/*`. Разрешение охватывает все пути и порты этого hostname. Оно не распространяется автоматически на `http://example.com/*` или `https://sub.example.com/*`. Путь страницы, query, hash и учётные данные в запрос не входят.

Доступ действует во всех вкладках и в iframe с разрешённым hostname, даже если такой iframe встроен в другую верхнюю страницу. И наоборот: разрешение верхней страницы не даёт доступа к iframe другого сайта. Для него нужен отдельный grant.

`activeTab` позволяет определить активную страницу при открытии popup; это временное право не заменяет постоянный host grant. Background регистрирует content script только для явно выданных точных scope. Широкие legacy grants не запускают сбор всех сайтов автоматически.

Внутренние страницы браузера, собственные extension URL, защищённые страницы Chrome Web Store и Firefox Add-ons недоступны. Браузер может дополнительно ограничивать корпоративные или другие защищённые страницы; ошибка инъекции не отображается как пустой результат.

## Состояния и восстановление

| Состояние                    | Что делать                                                  |
| ---------------------------- | ----------------------------------------------------------- |
| Нет доступа                  | Разрешить доступ выбранному сайту.                          |
| Требуется перезагрузка       | Перезагрузить вкладку отдельной кнопкой.                    |
| Сбор запускается             | Дождаться подтверждения установки bridge.                   |
| Обработчики не найдены       | Сборщик запущен, но доступных записей пока нет.             |
| Ограниченный результат       | Учесть ограничения контекстов и лимит записей.              |
| Ошибка проверки или действия | Повторить проверку; при необходимости открыть popup заново. |
| Страница недоступна          | Перейти на поддерживаемую HTTP/HTTPS-страницу.              |

Host grants сохраняет браузер. Background восстанавливает динамические регистрации при запуске и обновлении расширения. Записи обработчиков живут в памяти и после перезапуска background не восстанавливаются. Чтобы снова запустить сбор, нужна перезагрузка страницы. Она также нужна после возврата документа с остановленным сборщиком из BFCache.

## Остановка и ограничения

Отзыв из popup останавливает доступные сборщики, удаляет host grant и регистрации. Внешний отзыв через настройки браузера также запрещает приём новых записей и очищает результаты.

После внешнего отзыва браузер может закрыть канал связи с уже открытым документом. В таком случае полное удаление оставшихся page hooks требует перезагрузки страницы. Background не должен принимать их сообщения после отзыва. Сторонние patches, установленные страницей после hook расширения, не перезаписываются при остановке.

Запуск на `document_start` остаётся best effort: проверка доступа и установка bridge занимают время, поэтому ранние регистрации могут быть пропущены. Наличие разрешения не доказывает, что сборщик запущен. Покрытие `about:blank` и `srcdoc` зависит от подтверждённого браузером origin; без него контекст недоступен. Worker-контексты в MVP не поддерживаются.

## Ручная проверка нативного запроса

Firefox harness управляет настоящим диалогом `permissions.request` через Marionette. Программный grant в тестовом профиле сам по себе проверяет сбор и изоляцию, но не подтверждает нативный диалог. Для Chrome проверяем его вручную; следующий сценарий также подходит для повторной проверки Firefox с установленной сборкой на чистом профиле:

1. Открываем сайт без разрешения. Открытие popup не запускает сбор.
2. Нажимаем «Разрешить для этого сайта» и отклоняем запрос. Доступ не появляется; повторный запрос доступен.
3. Повторяем запрос, подтверждаем его и проверяем, что запрошен только выбранный hostname и схема.
4. Перезагружаем вкладку и проверяем появление заранее известного обработчика.
5. Открываем второй hostname: доступ к нему не выдан.
6. Отзываем доступ из popup; проверяем очистку результатов и отсутствие новых записей в двух вкладках сайта.
7. Повторно выдаём доступ, затем отзываем его через настройки браузера при открытом popup. Результаты исчезают; при необходимости перезагружаем страницы для удаления оставшихся hooks.
8. Перезапускаем браузер. Отозванный сайт не активируется снова; сохранённый grant другого сайта восстанавливается.

Этот сценарий остаётся обязательной ручной проверкой, пока автоматический harness не управляет настоящим нативным диалогом. Наличие сборки или mock вызова permissions API его не заменяет.
