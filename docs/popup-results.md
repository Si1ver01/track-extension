# Панель результатов

После выдачи доступа и перезагрузки страницы popup показывает полученные записи по типам событий. Каждая карточка сохраняет свой frame и document: обработчики из разных контекстов не сливаются.

Все 37 типов из [локального каталога](event-catalog.md) имеют русское описание назначения события. Описание помогает понять тип регистрации; поведение callback расширение не анализирует.

## Поиск

В поле «Поиск по метаданным» вводим тип события, путь цели или другие известные метаданные. Например, `click button` оставляет записи, в метаданных которых встречаются обе подстроки. Регистр и пробелы по краям не влияют на результат; все слова должны встречаться в одной записи.

Поиск проверяет `eventType`, описание события, `source.path`, `source.target`, `source.sourceKind`, `frameId`, `documentId`, `contextKind` и `lifecycle`. Например, `removed` находит записи с удалённым обработчиком. Расположение скрипта, параметры, коды ограничений и произвольные дополнительные поля в поиск не входят.

Кнопка «Сбросить поиск» очищает запрос и возвращает фокус в поле. Поиск выполняется локально; запрос не сохраняется и не попадает в логи.

## Фильтры

Под поиском выбираем состояние обработчика, источник регистрации и фрейм. По умолчанию видны все записи. Выбранные фильтры и слова запроса действуют одновременно: запись должна соответствовать каждому условию.

| Фильтр                | Варианты                                                                          |
| --------------------- | --------------------------------------------------------------------------------- |
| Состояние обработчика | `active`, `removed`, `unknown` или все состояния.                                 |
| Источник регистрации  | `addEventListener`, свойство `on…`, inline-атрибут, неизвестный источник или все. |
| Фрейм                 | Главный фрейм (`frameId: 0`), конкретный вложенный фрейм или все фреймы.          |

Неизвестный источник означает, что в записи нет `sourceKind`. Он не зависит от состояния `unknown`: это два разных признака. Фильтры не уточняют достоверность регистрации и не доказывают выполнение callback.

Список фреймов строится по всему текущему снимку, а не по результатам поиска; номера упорядочены по возрастанию. Фреймы без полученных записей в список не попадают. Если выбранный фрейм исчез из обновлённого снимка, выбор сохраняется с пометкой «нет записей», а список результатов остаётся пустым до изменения условий или появления записей.

«Сбросить поиск» оставляет фильтры выбранными. Кнопка «Сбросить фильтры» появляется при выборе хотя бы одного фильтра; она очищает и фильтры, и запрос, возвращая фокус в поле поиска. Снимок записей и доступ к сайту при этом сохраняются. Для выбора с клавиатуры используем стандартные списки браузера; Tab переводит фокус к следующему элементу.

Все условия обрабатываются внутри popup. Они не сохраняются после его закрытия и не отправляются на страницу, в storage или по сети. DEBUG-лог содержит только счётчики записей, групп и активных фильтров.

## Экспорт JSON

«Экспорт всего снимка» сохраняет все полученные записи. «Экспорт выборки» применяет текущий поиск и три фильтра; пустую выборку тоже можно сохранить. Файл скачивается локально с именем `listener-lens-<scope>-<timestamp>.json`. Разрешение `downloads` не требуется.

Формат `listener-lens-snapshot`, версия `1`, содержит время экспорта, главный `documentId`, область `all` или `filtered`, счётчики и записи. `totalCount` относится ко всему снимку; `exportedCount` — к записям файла, `omittedCount` — к записям, отклонённым повторной проверкой формата. Запрос поиска в файл не попадает.

На границе экспорта повторно отбираем поля метаданных. Произвольные дополнительные поля, текст callback, payload, значения элементов, `source.options`, `scriptLocation` и переданные страницей описания не сохраняем; описание события берём из локального каталога. Путь цели содержит только имя тега, без атрибутов и текста элемента. Адрес сайта в файл не включаем.

`coverage` и `warnings` сохраняют предупреждения о недоступных фреймах, потерях из-за лимита и ранних регистрациях. Даже пустой файл не доказывает отсутствия обработчиков на странице. Расширение не передаёт экспорт по сети; место сохранения определяет браузер.

## Сравнение снимков

Нажимаем «Запомнить снимок», меняем страницу и смотрим различия. Popup получает обновления автоматически; «Обновить снимок» дополнительно запрашивает актуальное состояние без перезагрузки страницы. «Заменить базовый снимок» начинает сравнение заново, «Сбросить сравнение» освобождает базовый снимок.

Сравнение охватывает все записи независимо от поиска и фильтров. Показываем добавленные записи, отсутствующие в текущем снимке, изменения метаданных со значениями «до → после» и число записей без изменений. Состояния `active`, `removed` и `unknown`, источник, путь, параметры `capture`/`passive`/`once` и коды ограничений участвуют в сравнении; время захвата не считается изменением регистрации.

Записи сопоставляем по `frameId`, `documentId`, `contextKind` и `id`. Новый документ вложенного фрейма создаёт другую запись даже при совпадении `id`. Отсутствие записи не доказывает вызов `removeEventListener`: возможны смена документа фрейма и потеря данных из-за лимита. Изменение `lifecycle` показываем отдельно как изменение метаданных.

Базовый снимок хранится в памяти background и сохраняется при закрытии popup. Для каждой вкладки доступен один снимок, всего — до 8 вкладок по 200 записей; при превышении лимита вытесняется самый старый снимок. Новый главный документ, закрытие вкладки, отзыв доступа и перезапуск background очищают снимок. В Chromium браузер может остановить background при простое, поэтому базовый снимок не гарантирован на всю сессию браузера. Неполнота хотя бы одного снимка отмечается предупреждением. Импорта файлов, постоянной истории и записи в storage нет.

## Группы и счётчики

Группы упорядочены по `eventType`; внутри сохраняется порядок полученных записей. Счётчик «Показано записей» сравнивает число совпадений после поиска и всех фильтров с размером текущего снимка. Число рядом с типом события относится к отфильтрованной группе.

Считаем записи метаданных, включая `removed` и `unknown`. Состояние видно в свёрнутой карточке. Счётчик не означает число активных обработчиков на всей странице: ранние регистрации и недоступные контексты могут отсутствовать в снимке, а объём данных ограничен.

## Карточка записи

Нажимаем карточку или переводим фокус на её заголовок и нажимаем Enter либо пробел. Внутри показаны цель, путь, источник регистрации, расположение скрипта, frame, document, тип контекста и жизненный цикл. Доступные параметры `capture`, `passive` и `once` сохраняют значения `true` и `false`; отсутствие значения показано как «Неизвестно».

Если есть сведения о навигации, причины ограничений или дополнительные параметры источника, карточка показывает их как текст. Значения не превращаются в ссылки, HTML или сетевые запросы. Расширение не собирает код callback, значения полей и содержимое clipboard.

При обновлении данных того же документа запрос, выбранные фильтры и раскрытые карточки сохраняются. Смена вкладки, сайта или главного документа сбрасывает локальное состояние панели; отзыв доступа, перезагрузка и ошибка скрывают результаты. Отфильтрованные карточки удаляются из списка, поэтому при возврате в выдачу они свёрнуты.

## Переход к элементу

Раскрываем карточку и нажимаем «Показать элемент». Расширение прокручивает страницу к реальной цели регистрации и на две секунды добавляет рамку. Подсветка не перехватывает указатель, не вызывает `click`/`focus` и не меняет стили самого элемента. Для `window` и `document` отдельного DOM-элемента нет.

Связь с целью сохраняется слабой ссылкой внутри сборщика. `source.path` не используем как CSS selector: одинаковые теги не приводят к подсветке случайного узла. Поддерживаем доступные iframe и элементы открытого или закрытого Shadow DOM. Если цель — сам `ShadowRoot`, показываем его host с отдельным пояснением. Удалённый обработчик не мешает показать сохранившийся элемент.

Background проверяет источник команды, доступ к сайту и фрейму, текущие главный и вложенный документы и наличие записи. Если документ сменился, цель удалена, скрыта или потеряна из ограниченного реестра, popup объясняет отказ. Вместо поиска похожего элемента предлагаем обновить снимок. Ссылки ограничены 4000 записями и не передаются в JSON или storage.

Повторная подсветка заменяет предыдущую в этом документе. Таймер, уход со страницы и остановка сборщика убирают рамку; отзыв доступа очищает связи с целями. Подсветка работает best effort: страница может перекрыть или удалить рамку. Bridge страницы не служит криптографической аутентификацией, поэтому проверка разрешений остаётся в background.

## Покрытие сбора

Над результатами popup объясняет каждую известную причину неполного покрытия. Причины независимы и могут появляться одновременно.

| Причина                | Что означает                                                                                        | Действие                                                                                             |
| ---------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `FRAME_PARTIAL`        | Покрытие фреймов неполное: встречен другой адрес, неподтверждённый origin или недоступный контекст. | Для фрейма другого сайта открываем его отдельно, выдаём доступ и перезагружаем исходную вкладку.     |
| `RECORD_LIMIT_REACHED` | Потеряны записи из-за лимита буфера вкладки, локального снимка документа или реестра детектора.     | Учитываем, что поиск работает только по сохранённым записям; для нового сбора перезагружаем вкладку. |

Буфер хранит до 200 последних добавленных записей. Обновление существующей записи сохраняет её позицию и само по себе не означает переполнение. Ограничение появляется после фактической потери данных и сохраняется до нового сбора главного документа. Реестр `addEventListener` и реестр property/inline slots ограничены 2000 записями каждый; новые регистрации сверх лимита имеют `unknown`, а ранее учтённые продолжают обновляться.

Для восстановления content script хранит до 200 очищенных записей каждого документа. После перезапуска background или возврата из BFCache живой сборщик передаёт их заново с прежними ID и актуальным жизненным циклом. Переполнение локального снимка сохраняется при восстановлении; оно не превращается в полный результат. Общий снимок вкладки по-прежнему ограничен 200 записями.

Кнопка «Перезагрузить вкладку» доступна при ограниченном покрытии. Она скрывает текущие результаты на время запуска нового сбора. Если вкладка уже перешла на другой сайт, действие отменяется и popup обновляет состояние. Перезагрузка не выдаёт разрешений другим сайтам.

Если background вернул `limited` без подробностей, popup показывает общее пояснение. Даже при `ready` сохраняется предупреждение о регистрациях до установки hook.

Property handler и inline-атрибут — отдельные наблюдаемые поверхности с `SURFACE_UNVERIFIED`. Их наличие не доказывает, что браузер исполняет два callback: обе поверхности могут относиться к одному нативному слоту. Замена, удаление и повторное добавление обновляют запись с прежним ID.

## Пустые результаты

| Сообщение                                | Значение                                                                                                          |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Обработчики событий не найдены.          | Готовый сборщик вернул пустой снимок. Это не гарантирует отсутствие ранних или недоступных регистраций.           |
| Пока нет данных об обработчиках.         | При ограниченном покрытии снимок пока пуст; отсутствие обработчиков не подтверждено.                              |
| По запросу ничего не найдено.            | В снимке есть записи, но фильтр не нашёл совпадений. Можно сбросить поиск.                                        |
| По выбранным фильтрам ничего не найдено. | В снимке есть записи, но их пересечение с поиском и фильтрами пусто. Можно изменить условия или сбросить фильтры. |
